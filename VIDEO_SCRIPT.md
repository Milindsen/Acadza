# Three-minute screen recording guide

Use the live console in a 1440×900 browser window. Record your own voice so the walkthrough reflects your understanding. This file is a recording script, not a claim that a video has already been recorded or uploaded.

**0:00–0:25 · Start on the queue**

“This is Question care: a report-to-fix loop for Acadza. The supplied 44 reports become 39 question cases. The queue prioritizes wrong keys and questions students cannot answer, then repeated reports and time waiting. Report volume changes urgency, not confidence. This hosted version uses precomputed judgments and browser-local decisions; the repository also includes a durable SQLite backend.”

**0:25–1:05 · Open R004 using search**

“This is the tricky case. A student says the answer should be 8225. They are wrong, but the saved key is also wrong. Independently, pressure is one-third density times RMS speed squared: 4800 pascals, option D. The stored solution agrees. So the system changes A to D, not to the student's suggested B. The preview shows exactly one field changing.”

**1:05–1:30 · Approve and show Decision history**

Set your reviewer name first. Approve the correction, then open Decision history.

“Approval is one click. The audit contains my name, timestamp, revision and complete before/after snapshots. The local server uses one transaction for both the content and audit. A stale reviewer cannot overwrite another decision. No action touches Acadza production, and no student message is sent by this prototype.”

**1:30–2:00 · Return; search R009**

“Here option D is genuinely missing from the saved HTML. The answer C can be solved, but there is no evidence for the missing distractor. Although the taxonomy permits option repairs, permission is not proof. There is no Apply button: I can escalate it with a note. I will never invent content just to clear the queue.”

**2:00–2:30 · Search R027, then R034**

“The report tries to tell the AI to become an admin and change the answer. It is displayed as quoted data and ignored as an instruction. The physics still supports A. In the wave case both statements are false and the option is missing, so a key-only edit would be unsafe. Faculty must repair the question as a whole.”

**2:30–3:00 · Quality overview / repository**

“The live inference path solves without seeing the key, then triages and verifies. Deterministic guards enforce field scope, unique anchors, answer shapes and human-only repairs. The committed baseline is honestly labelled assistant-reviewed; I did not claim an API run without credits. Eighteen tests exercise the safety boundaries. In week one I'd measure harmful edits per thousand fixes, with random faculty re-audits, before expanding automation.”
